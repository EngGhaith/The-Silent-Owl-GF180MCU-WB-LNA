Analog Pad Model Comparison

S-parameter impact of swapping the gf180mcu_fd_io__asig_5p0 RF pad model, across both project branches. Four simulation runs, one 2.4 GHz LNA core, four different pad netlists.

GF180MCU asig_5p0 pad 1–5 GHz sweep target band 2.3–2.5 GHz
main and main_pex already used two different pad models before this comparison — main's own netlist is a 112-line "manually scaled" extraction, main_pex's is a full 102,486-line Magic PEX extraction. So this isn't really one 4-way comparison: it's two separate pairs, each testing the repo's 6-pin fully-extracted model (JuanMoya/sscs-chipathon-2025) against whatever that branch already had.

04What stands out

Return loss

On main, S11/S22 both move from a healthy −13.7 / −17.0 dB to a much weaker −4.6 / −4.9 dB with the repo's extracted pad — the real bond-pad parasitics are a substantial mismatch main's matching network wasn't tuned for.

Gain

S21 actually improves on main (16.8 → 20.4 dB going the other way) since the extracted pad model is the lossier one here, pulling gain down more than the plain 4-device model does.

main_pex is closer

main_pex's own PEX model already carries real pad parasitics, so swapping to the repo's extracted model is a smaller jump: S11 −16.0→−11.5 dB, S22 −25.9→−8.1 dB — still a real shift, especially on S22.

Noise figure

NF stays within ±0.2 dB across every variant tested at 2.4 GHz — the pad's loading mostly reshapes the match, not the noise contribution.
