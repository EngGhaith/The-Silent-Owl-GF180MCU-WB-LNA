Retuning one LNA core to four bands: what changed, and what survived

Starting from dev_ilir and dev_ghaith (both tuned for 2.3–2.5 GHz), we built 8 branches — each topology × GNSS L1 (1575.42 MHz), GNSS L2 (1227.60 MHz), LoRa EU868 (868.30 MHz) and LoRa EU433 (433.92 MHz) — by resizing and adding passive components only, never touching an inductor or the core topology. This page documents exactly what moved in each schematic and what the re-simulated S-parameter/noise bench actually shows for all 8, then explains why only three branches are being carried forward.

01

What changed in each schematic

Every change is a passive value: an existing shunt cap resized, a new shunt cap added in parallel with an existing tank/match element, or (where the frequency shift demanded it) an existing series AC-coupling cap resized. No inductor was changed and no transistor was resized or re-biased beyond the one dev_ilir base rebias noted below.

dev_ilir 3-transistor CG→cascoded-CS core, passive source degeneration
  • Base change (all 4 variants): VBIAS_CG 2.2V→1.0V in the testbench — cuts M2's current ~85%, merged as PR #17.
  • 3 shunt caps added at every band: CTUNE_IN (rf_in_pad‖vss, parallels Rs1/Lmatch), CTUNE_M2 (vm2‖vdd, parallels RLD3/LD4), CTUNE_OUT (vout_tank‖vdd, parallels RLD2/LD2).
  • GNSS L2 / LoRa EU868 / LoRa EU433 only — a 4th cap, CTUNE_DEG, added at M2's source-degeneration node (parallels Rs/L1). That branch's impedance shrinks with frequency and starts shunting signal to ground once it drops below M2's 1/gm; CTUNE_DEG anti-resonates it back up near the target frequency.
  • GNSS L2 / LoRa EU868 / LoRa EU433 only — series cap C15 enlarged (the direct AC-coupling path from the pad into M2's source): 1.5p→3p / 20p / 35p respectively. This was the single biggest lever in the whole study — see §03.
dev_ghaith 4-transistor CG core, active current-sink degeneration
  • No base bias change — left at the original 2.2V/1.9V defaults throughout.
  • 2 shunt caps added at every band: CTUNE_M2 (vm2‖vdd) and CTUNE_OUT (vout_tank‖vdd) — same two tank nodes as dev_ilir.
  • Existing input shunt cap C5 resized instead of adding a new one (rf_in_pad‖vss is already capacitive here, not inductive) — down to a practical floor (0.5µm²) at every band; the first-pass formula had badly overshot it.
  • No degeneration-cap equivalent needed — M5 is an active current-sink setting M2's bias current, so that branch's impedance doesn't collapse with frequency the way dev_ilir's passive Rs/L1 does.
  • GNSS L2 / LoRa EU868 / LoRa EU433 only — series cap C2 enlarged (the coupling cap from the input match network into M2's source): 30.2µm²→40 / 50 / 100µm² respectively.

03

Full numbers

Why only three branches move forward

LoRa EU433 is out on both topologies, structurally. At 5.5× below the 2.4 GHz design point, neither branch reaches positive gain (dev_ilir −9.4 dB, dev_ghaith −5.9 dB) even after an extensive search that also freed the series caps and every live bias pin. That's not an under-tuned corner — it's a hard limit of this core at this frequency ratio.

That leaves GNSS L1, GNSS L2 and LoRa EU868, where both topologies technically work. Picking dev_ghaith's three over dev_ilir's equivalent three comes down to:

  • Lower current, no rebias required: dev_ghaith draws 15.1 mA at every band, un-touched from its original design point. dev_ilir needs 22.2 mA — and that's only after the separate VBIAS_CG rebias in PR #17; without it, dev_ilir runs M2 at ~60 mA alone.
  • Dramatically better input match on 2 of 3 bands: S11 of −21.8 dB and −35.0 dB (GNSS L2, LoRa EU868) vs. dev_ilir's −9.2 dB and −5.2 dB — the latter barely clears the −10 dB spec at all.
  • No structural degeneration-inductor weakness: dev_ilir's passive Rs/L1 source degeneration is the component that breaks down hardest as frequency drops (it needed its own dedicated anti-resonance cap, CTUNE_DEG, just to stay usable) — the same mechanism that makes LoRa EU433 unrecoverable on that branch specifically. dev_ghaith's active-sink degeneration doesn't carry this risk at all.
  • Fewer added components per band: 2 shunt caps + 1 resize vs. dev_ilir's 3–4 shunt caps + 1 resize — a smaller, simpler change set to validate and lay out.

dev_ilir's own GNSS L1/L2/EU868 variants are not broken — they're genuinely close competitors. But for carrying exactly one topology forward across three bands, dev_ghaith wins on every axis that matters beyond raw gain.
