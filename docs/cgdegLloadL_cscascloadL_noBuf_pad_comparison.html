cgdegLloadL_cscascloadL_noBuf — generic pad vs. 0 Ω PEX pad

CG (no cascode, inductive source degeneration, inductive drain peaking) → CS+cascode (inductive drain peaking), passive output match, no buffer. Centered at 2.4 GHz. Two branches of the same core circuit, differing only in which I/O ESD pad model terminates the RF ports.

This design is carried over unmodified from the archived dev_ilir_inductive_degen branch (commit 05107ff). Only the testbench (pad model, control script) was changed for cgdegLloadL_cscascloadL_noBuf; input/output matching (LIN/RLIN/C11) was additionally re-tuned for cgdegLloadL_cscascloadL_noBuf_pex to account for the real extracted pad's parasitics.

Pad-model issues found and fixed

Both testbenches instantiate gf180mcu_fd_io__asig_5p0 exactly as the symbol netlists it (port order ASIG5V DVDD DVSS VDD VSS, from the symbol's own pinnumber attributes). Three independent, unrelated problems were found and fixed while wiring the real pad models up to this testbench:

1. Raw PDK pad model crashes ngspice-47 (generic-pad branch)

.include /foss/pdks/gf180mcuD/libs.ref/gf180mcu_fd_io/spice/gf180mcu_fd_io.spice — i.e. the pad model literally referenced in the inherited testbench, unmodified — deterministically aborts netlist load in this ngspice build: 
Error on line 1412 or its substitute:
  g.x2.x1.gc_moscap x2.x1.c_moscap_int1 0 0 vddio   3.600000000000000e+01    e9
  unknown parameter (e9)
Reproduced with a minimal 5-line standalone reinstantiation of just the asig_5p0 subcircuit, independent of everything else in the testbench. Root cause: the PDK cell instantiates its ESD MOS capacitor with a device multiplicity (m=36); elaborating that with this ngspice build corrupts an internal line while expanding the cap_nmos_06v0 compact model. This is the same cap_nmos_06v0 "m=" elaboration bug already worked around elsewhere in this project by expanding the multiplicity into individual unit-size instances instead of using "m=". Fix: xschem/gf180mcu_fd_io__asig_5p0_generic_pinfixed.spice (co-located with the testbench) reuses the project's own capacitance-extracted pad model (analog_pad_sp_paramerters/spice_files/extracted_gf180mcu_fd_io__asig_5p0_manually_scaled.spice, which already instantiates 36 individual unit MOS caps instead of one with m=36), with its .SUBCKT pin order corrected to match the symbol.

2. 0 Ω PEX extraction never ties its ASIG5V port into its own RC mesh

Every other port of the flat extraction (DVDD, DVSS, VDD, VSS) has an explicit element tying the bare port name into its parasitic mesh (e.g. R30992 DVDD.n5553 DVDD 0.456503). ASIG5V has none — every reference to it inside the extraction is a suffixed sub-node (ASIG5V.n9972, ASIG5V.t0, ...), never the bare port name, so the RF signal pin is only coincidentally connected through whatever the generic pad fix handled. Fix: a single tie resistor was added at the end of the subcircuit, bridging the port to a well-connected hub node of its own mesh: 
R_ASIG5V_PIN_TIE ASIG5V ASIG5V.n9972 0.01

3. Pin-order mismatch in the PEX pad's own .SUBCKT declaration

The 0Ω PEX file's .SUBCKT line read gf180mcu_fd_io__asig_5p0 DVDD ASIG5V DVSS VDD VSS — the first two pins swapped relative to the symbol. Internal nodes are name-based, so only the port names on the .SUBCKT line needed to change, to ASIG5V DVDD DVSS VDD VSS.

Both fixed pad models now live next to their testbench (xschem/gf180mcu_fd_io__asig_5p0_generic_pinfixed.spice and xschem/gf180mcu_fd_io__asig_5p0_pex__pdk_gf180mcuD__rcx__flat__cthresh_0__extresist_0mohm.spice respectively) and are referenced via $::env(PWD)/<filename> in the testbench's MODELS block, so the include resolves next to whichever checkout/worktree the branch lives in, rather than to a hardcoded absolute path.

Matching re-tune for the PEX pad

The 0 Ω PEX pad presents a markedly different impedance at the RF pins than the generic model once correctly wired up (far more parasitic capacitance from the full RC mesh). Re-sweeping the input L-match (LIN, RLIN) against the real PEX pad moved the optimum from 7 nH/14 Ω to 5.5 nH / ≈0 Ω (removing RLIN's loss entirely), improving in-band S11 from roughly −2 dB back to the −3.2 to −4.0 dB range the generic-pad branch already had. The output network (C11 = 0.8 pF, unchanged) turned out to already be close to a local optimum for S22 against the PEX pad as well — sweeping it from 0.15 pF to 5 pF never beat the as-inherited value.

Reproducing these results

Each branch's testbench (xschem/lna-core_tb.sch) is self-contained: run it directly from its own xschem/ directory (so the $::env(PWD) pad-model include resolves) and it reproduces the S-parameter, noise-figure and stability numbers above. The control script was also trimmed of a large block of dead op-point/noise-cancellation code inherited from a different (parallel CG/CS noise-cancelling) architecture that doesn't exist in this circuit — see the testbench's own comments for what was removed and why.
