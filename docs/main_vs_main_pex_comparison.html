How to go from main (gen_v4) to main_pex (singleL)

The core CG/CS/cascode stage, bias point, and degeneration/drain-tank values never change — only the pad-facing matching network is retuned, because the real PEX-extracted pad presents far more parasitic capacitance than the generic pad.

  1. Swap the pad model. Replace the .include of gf180mcu_fd_io__asig_5p0_generic_pinfixed.spice with the real PEX-extracted netlist (gf180mcu_fd_io__asig_5p0_pex__pdk_gf180mcuD__rcx__flat__cthresh_0__extresist_0mohm.spice).
  2. Shrink the input shunt inductor. LEQ: 2.8491n → 1.3333n (more pad capacitance resonates at the same frequency with less inductance). RLEQ follows at Q=12: 3.58Ω → 1.68Ω.
  3. Remove the Pi-match capacitor. Delete CPI (1.445p) entirely — it isn't needed once the real pad's own capacitance plus the restored output shunt take over the bandwidth-shaping role.
  4. Shrink the input series cap. C15: 2.4303p → 1.25p.
  5. Grow the output series cap substantially. C11: 2.2142p → 7p.
  6. Re-populate the output shunt inductor. Add back LSHUNT_OUT = 2.5n and RLSHOUT = 3.1416Ω (Q=12) between rf_out_pad and vss — this was DNP in gen_v4 because the lighter generic pad didn't need it; the real pad's heavier capacitance does.
  7. Leave everything else untouched — core transistor sizes, bias voltages, L1/Rs degeneration, and LD2/RLD2 drain tank are identical between the two.
main: gen_v4 circuit, generic pad (official PDK content only, m=36 MOS-cap elaboration workaround for ngspice-47), pin order verified against the symbol. main_pex: dev_ilir_pexmatched_singleL circuit, real PEX-extracted pad; testbench fixed to run on a fresh checkout (Tcl script execution re-enabled, pad netlist co-located in xschem/). Both verified end-to-end: netlist → ngspice → S-parameters bit-for-bit matching their respective already-published numbers.
